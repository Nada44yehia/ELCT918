## 1. Project Overview

This project implements a Sparse Processing Element (PE) based on the Fine-Grained Structured Sparsity (FSS) technique presented in the paper:

**"Fine-Grained Structured Sparse Computing for FPGA-Based AI Inference."**

The design accelerates sparse matrix-vector multiplication (SpMxV) by dividing each weight row into multiple banks and retaining a fixed number of weights from each bank.

Instead of processing all weights, the PE processes only the retained weights using parallel multipliers and an adder tree, followed by sequential accumulation of the partial sums.

The design is implemented using Verilog HDL and verified using a Verilog testbench and a Python reference model.

## 2. FSS Configuration

The current implementation uses the following configuration:

| Parameter | Value |
| Number of banks | 4 
| Elements per bank | 8 
| Total row size | 32 
| Retained weights per bank | 4 
| Total retained weights | 16 

| Sparsity | 50% 
| Weight precision | Signed INT8 |
| Input vector precision | Signed INT8 |
| Accumulator precision | Signed INT32 |

Each 32-element weight row is divided into four contiguous banks:

- Bank 0: Elements 0–7
- Bank 1: Elements 8–15
- Bank 2: Elements 16–23
- Bank 3: Elements 24–31

Four weights are retained from each bank according to their absolute magnitudes.

The retained weights and their corresponding bank-local indices are stored in Compressed Sparse Blocks (CSB) format.

## 3. Architecture

The design consists of the following main blocks:

### 3.1 Vector Buffer

- Stores the complete 32-element input vector.
- Organized as four independent banks.
- Each bank contains eight signed 8-bit elements.
- Supports one write operation per clock cycle.
- Provides four independent synchronous read ports.
- Uses bank-local indices to retrieve the corresponding vector elements.

The global vector address is divided into a bank address and a local address:

- Bank address = `vec_waddr[4:3]`
- Local address = `vec_waddr[2:0]`

### 3.2 CSB Controller

The CSB controller stores the compressed weights and their corresponding indices.

It contains:

- CSB weight memory: 16 entries, signed 8-bit.
- CSB index memory: 16 entries, 3-bit.
- A three-state FSM: IDLE, SEND, and WAIT.
- A two-bit group counter.

The controller supplies four weights and four indices per group.

It generates:
- `group_valid`: Indicates that the current group is ready for accumulation.
- `last_group`: Indicates that the current group is the final group.
- `busy`: Indicates active processing.
- `done`: Indicates completion of the row operation.

The controller uses the SEND state to present the current group and the WAIT state to allow the registered datapath and accumulator to process it.

### 3.3 Weight Registers

Four signed 8-bit registers store the current group of weights.

They ensure that the weights are aligned with the corresponding registered vector-buffer outputs.

### 3.4 MAC Tree

The MAC tree performs four multiplications in parallel.

Each multiplication produces a signed 16-bit result.

The four products are sign-extended and added using a two-level adder tree:

1. First level: Two pairs of products are added.
2. Second level: The two intermediate sums are added.

The resulting partial sum is signed 18-bit.

### 3.5 Accumulator

The accumulator receives the partial sum generated by the MAC tree.

It:
- Sign-extends the 18-bit partial sum to 32 bits.
- Adds the partial sum to the accumulated result.
- Stores intermediate sums.
- Stores the final result when `last_group` is asserted.
- Generates a one-cycle `row_done` pulse.

The accumulator uses a synchronous active-low reset.

## 4. Processing Flow

For each row:

1. The Python script generates the original weights and input vector.
2. The FSS encoder divides the weight row into four banks.
3. Four weights are retained from each bank.
4. The retained weights and local indices are rearranged into CSB format.
5. The testbench loads the vector buffer.
6. The testbench loads the CSB memories.
7. The testbench asserts `start`.
8. The CSB controller sends four groups sequentially.
9. The vector buffer retrieves four corresponding vector elements per group.
10. The MAC tree calculates four parallel products and generates a partial sum.
11. The accumulator adds the four partial sums.
12. The final result is checked against the Python reference.

## 6. Python Reference Generation

The Python script performs the following operations:

- Generates reproducible signed INT8 weights and vector elements.
- Divides the weight row into four banks.
- Selects four weights per bank using their absolute magnitudes.
- Uses stable sorting for deterministic tie-breaking.
- Sorts selected local indices in ascending order.
- Rearranges retained weights and indices into group-major CSB format.
- Calculates the expected sparse dot product.
- Generates memory initialization files for RTL simulation.

The random seed is fixed to ensure reproducible results.

Current configuration:

```python
NUM_BANKS = 4
BANK_SIZE = 8
ROW_SIZE = 32
KEEP_PER_BANK = 4
SPARSITY = 0.50
SEED = 17
```

Run the Python script before starting the simulation to generate the required memory files.

## 7. Simulation

The RTL can be simulated using QuestaSim or another Verilog-compatible simulator.

### Step 1: Generate input files

Run the Python encoder to generate the `.mem` files and expected reference result.

### Step 2: Compile the RTL

Compile the required RTL modules and testbench.


### Step 3: Run the simulation

```bash
vvp sparse_pe_sim
```


**Important:** Run the simulation from a working directory where the generated memory files are accessible, or update the `$readmemh` file paths accordingly.

## 8. Verification

The design is verified by comparing the RTL result with the Python reference result.

The testbench checks:

- Vector buffer loading.
- CSB weights and indices loading.
- Four-group controller operation.
- Vector reads using bank-local indices.
- Signed multiplication.
- Adder-tree operation.
- Accumulation of partial sums.
- Final result and completion signals.

### Example standalone PE test

A standalone datapath test uses the following groups:

| Group | Weights | Local indices | Partial sum |
|---|---|---|---:|
| 0 | 1, 2, 3, 4 | 0, 0, 0, 0 | 170 |
| 1 | 1, 2, 3, 4 | 1, 1, 1, 1 | 180 |
| 2 | 1, 2, 3, 4 | 2, 2, 2, 2 | 190 |
| 3 | 1, 2, 3, 4 | 3, 3, 3, 3 | 200 |

Expected result:

```text
Expected result = 740
```

A separate Python-generated comparison test can use the generated CSB data and its corresponding expected result.

### Completion criteria

The test passes when:

```verilog
result == expected_result
row_done == 1'b1
```

For the integrated controller, `done` should also assert when the final group has been processed.

## 9. Dense Baseline Comparison

A dense baseline PE is included to compare the FSS implementation against conventional dense processing.

The baseline:
- Stores the complete 32-element pruned weight row.
- Stores the complete 32-element input vector.
- Processes four consecutive elements per cycle.
- Uses four parallel multipliers and an adder tree.
- Processes all 32 positions, including pruned weights represented by zeros.

The sparse PE processes only the 16 retained weights.

| Feature | Sparse PE | Dense Baseline |
|---|---:|---:|
| Original row size | 32 | 32 |
| Retained weights | 16 | 16 |
| Processing groups | 4 | 8 |
| Parallel multipliers | 4 | 4 |
| Useful MAC operations | 16 | 16 |
| Zero-weight multiplications | Avoided | Not avoided |

The sparse PE reduces the number of processed positions by 50% while preserving the same pruned-row dot-product result.

## 10. Design Notes

- All arithmetic uses signed two's-complement representation.
- INT8 × INT8 produces a signed 16-bit product.
- The MAC tree uses an 18-bit partial sum.
- The accumulator uses a signed 32-bit result to avoid overflow for the supported row configuration.
- Sequential state uses synchronous active-low reset.
- Vector and CSB loading are performed through RTL write interfaces.
- The vector buffer uses one write port, so loading 32 elements requires 32 clock cycles.
- CSB loading uses one write port, so loading 16 entries requires 16 clock cycles.
- Input loading overhead is measured separately from PE row-processing latency.
